# AI Bot Assist — 一体化依赖构建

当前构建会把Pi SDK、Bun运行环境及前置模组内嵌进JAR，玩家无需另行安装Bun/npm、下载Pi依赖或填写运行时路径。

## 玩家安装

1. 启动器安装Minecraft 1.21.1、Java21和对应Fabric或NeoForge加载器。加载器/游戏/Java本身不打入模组。
2. 只放入对应平台的一份模组JAR，不要同时安装两份。Architectury已内嵌；Fabric版额外内嵌Fabric API。
3. 游戏内执行 `/aibot settings`，填写API地址、模型和密钥或完成TokenNest授权。**自定义Pi路径留空使用内嵌运行时**；旧默认agent-runtime/index.mjs自动迁移到内嵌模式。
4. 首次调用自动校验并解包当前平台程序到config/aibotassist/runtime/<内容哈希>/，随后启动，不进行玩家侧网络依赖下载。磁盘必须可写且允许执行本地程序。

支持内嵌Windows x64、Linux x64/ARM64、macOS x64/ARM64。Windows ARM64及其它架构暂不内嵌。五平台一起提供会增大JAR：当前Fabric约163MiB，NeoForge约161MiB；首次解包还需一份本机程序磁盘空间。Linux/macOS仅交叉编译，仍待本机验证；系统运行库、执行权限或安全策略可能影响启动。

## AI 对话与状态面板

进入世界后按 **K** 打开 AI 对话，也可输入 `/aibot chat`。快捷键可在「选项 → 控制 → 按键绑定 → AI Bot Assist」修改。输入消息按 Enter 或点击「发送」；聊天窗口提供设置、清空记录、状态面板开关和「停止」按钮。仍支持原有 `@AI 消息`（使用设置中的 AI 名称）。窗口中的消息只进入本机 Agent，不作为玩家公开聊天发送到服务器。

窗口顶部显示准备、思考、工具执行、查询游戏任务进度和本轮结束等状态，并显示模型轮数、工具调用次数及耗时。「本轮结束」表示 AI 本轮回复结束；具体游戏操作是否成功以工具结果和 AI 回复为准。Esc 返回游戏，关闭窗口不停止任务，也不暂停单人世界；需要中止时点击「停止」。已经执行的游戏操作不会回滚。

游戏画面左下角仅显示 14×14 的半透明 AI 状态图标：绿色就绪、蓝色闪烁工作中、橙色失败、灰色未就绪；详细状态在 K 聊天窗口查看。可在聊天窗口直接开关，也可在「设置 → 界面」关闭、调整背景不透明度（15%～85%，默认 55%），点击「完成」保存。打开菜单/聊天窗口或按 F1 时隐藏 HUD，避免遮挡交互。聊天和草稿按服务器/单人存档来源、存档标识及实际玩家 UUID 加密保存在客户端，重进或重启后恢复。最多保留160条聊天，最近8条玩家/助手消息作为下一次请求的背景；「清空」保存当前会话的清空结果，不中止当前任务。旧任务不会自动恢复。详见 [多人会话隔离](docs/MULTIPLAYER_API.md)。

## 工具与功能

真实Pi Agent核心0.85.1驱动30个服务器游戏工具和5个客户端工具；详见 [工具参数及安全边界](agent-runtime/TOOLS.md)。独立模式由客户端保存个人凭据并发送模型请求，共享模式由服务器保存共享连接并转发；Pi不接收密钥，服务器裁决权限、模式、材料与世界操作。熔炼/酿造遵循原版tick，任务恢复限制见工具文档。

## 多人游戏 API 配置

默认 **每人独立配置 API**，各玩家使用自己的客户端密钥或 TokenNest 登录。管理员可在「设置 → 服务器 API」切换为**服务器共享 API**，填写地址、模型、密钥并保存；共享后玩家无需个人登录，共享密钥保存在服务器，不回传玩家。对话和任务仍按玩家隔离，游戏权限照常检查。

也可编辑 `config/aibotassist-server-api.json` 后执行 `/aibot api reload`。支持 `/aibot api mode independent` 和 `/aibot api mode shared`，首次创建配置为 independent。共享模式的对话和截图经服务器转发，客户端会显示此模式。具体步骤、配置示例及限制见 [多人 API 说明](docs/MULTIPLAYER_API.md)。

## 让 AI 查看当前视野

对 AI 说“看看我眼前有什么”或“看一下这栋房子的外观”，Agent 可调用 `capture_view` 截取当前游戏视野，再根据图片回答。需要选择支持**图片输入及工具调用**的模型。画面跟随当前第一/第三人称相机，截取时避开菜单及 AI 面板，包含原版 HUD；不会读取桌面或其他应用。图片仅在内存处理，发送给当前配置的模型服务，不写截图文件。每次请求最多3次截图，不持续录屏。

存档所有者/服务器 OP 还可让 AI 控制自己的创造模式假人，并通过 `capture_fakeplayer` 从指定眼睛坐标渲染有限区域，无需移动真实玩家。图像采用客户端方块模型与纹理，不包含实体和动态机器动画；参数与限制见 [假人控制与远程取景](docs/FAKEPLAYER.md)。

视野工具仅需客户端安装，即便服务器没有本模组也能查看画面。操作世界仍需服务器工具授权。图片供视觉参考，精确坐标和操作结果仍需实际观察/验证。窗口最小化或停止渲染时可能无法截图；不支持图片的模型可能返回请求不兼容提示。

## 建造上限和图片校准

在「设置 → 建造」调整**单次方案方块上限**，默认为 **4096**；填写 **0** 或点击「无限制」可取消方块数量限制。放置、门/床扩展和清障都计数，旧的累计1024格限制已移除。设置在下一次请求生效；无限模式仍遵守当前建造空间范围、材料、服务器权限及运行预算。

大方案会分包上传，由服务器分批执行，门和床的两部分保持同批，完成后检查整份方案。同一次玩家请求的建筑原点与朝向固定，走动或转身不会使下一批偏移。AI 可用盒体/椭球参数描述立体造型，减少逐格生成的负担。

「建造后图片校准」默认开启：建造后读取画面，模型按需修正再查看，截图失败会明确说明未完成外观复核。该功能需要支持图片输入的模型，也可在建造设置中关闭。升级时请同时替换客户端和服务器的模组 JAR。

## 通用模组、地图、存档与机器协作

新增 JEI 配方读取、Xaero 当前地图路标/地图截图、整存档后台快照、机器状态/红石输入检查、崩溃日志诊断和管理员指令协作。JEI、Xaero 均为可选模组，不会随本模组强制安装。模型可以先查询真实配方、机器及方块属性，再规划和检查产线。

可直接对 AI 说：“根据 JEI 查这个物品的生产步骤”“检查眼前漏斗为什么不出货”“给我建一个自动熔炉”“按这个配方建单原料自动合成器”“读取最新崩溃报告”。自动合成器模板仅处理单一原料可填充的普通配方，包含空槽禁用、供料和输出；红石时钟默认未启动，完成建造后仍需验证运行。混合原料和模组多方块结构需要依据实际机器规则设计，通用兼容不代表已经支持每种工业模组的自动配置。

完整存档及服务器日志限单人存档所有者/服务器 OP 读取；高级命令使用玩家实际作弊/OP权限，不自动提升权限。快照复制整个存档（含未加载区块），后台进行，非原子备份；副本保留在存档父目录 `.aibotassist-snapshots`。JEI 可直接读取槽位和机器；Xaero 路标只读当前会话所选地图，`capture_map` 需先打开 Xaero 世界地图并保持可见，不解码其私有地形缓存。

具体参数、权限、快照保留规则和测试边界见 [通用兼容说明](docs/MOD_COMPATIBILITY.md)。客户端和服务器请同时更新对应加载器的 JAR。

## 开发构建

构建机仍需Java21和Bun（不是玩家依赖），Gradle自动运行bun install --frozen-lockfile及五平台独立编译，将资源嵌入两平台JAR。可通过`-PbunExecutable=绝对路径`指定构建用Bun。首次构建需要下载依赖及跨平台Bun目标；项目内已有锁文件、依赖目录和已生成运行时，分发JAR不要求玩家下载。SDK源码通过固定包和锁文件提供，不将node_modules提交Git。

```powershell
$env:JAVA_HOME='D:\Program Files\Java\jdk-21'
.\gradlew.bat build
```

发布产物：fabric/build/libs/aibotassist-fabric-0.2.0.jar、neoforge/build/libs/aibotassist-neoforge-0.2.0.jar。0.2.0为本次完整构建，安装前移除旧版本JAR。

验证记录见 [VERIFICATION.md](VERIFICATION.md)。

## 0.2.0 本地凭据

TokenNest OAuth 的默认 client_id、回调 URI、scopes 和后台创建请求见 [登录配置](docs/TOKENNEST_LOGIN.md)。
游戏设置支持直接发起登录、查看授权状态、取消等待和复制服务器注册参数。

API密钥及TokenNest access/refresh token保存在玩家电脑客户端 `config/aibotassist/private/`，采用AES-256-GCM加密及世界绑定AAD；`local.key`为同机解密密钥，密文以哈希文件名隔离，不含可读世界路径。单人绑定存档绝对路径，联机绑定连接地址，再结合登录玩家UUID。不同维度共享同世界记录；多人服务器内部更换世界无法由客户端可靠识别，仍按服务器地址区分。

进入世界加载，离开清理内存，刷新令牌后更新保存；修改API地址或OAuth client_id清除当前内存授权，不能把旧服务商令牌带到新端点。设置中“清除当前世界凭据”删除该世界本地记录，不影响其它记录。退出游戏不会删除已保存记录。OAuth浏览器回调绑定发起世界，切换世界后不接受旧登录结果。

个人登录凭据不传到Minecraft服务器、Pi进程或世界存档。管理员配置共享模式时，新共享密钥会单独提交服务端保存，既有共享密钥不回传客户端。不要分享整个config目录及local.key。加密密钥与密文都在本机，因此不能抵抗同系统账号恶意程序/文件窃取；Windows使用系统继承ACL，Unix尽力设为仅所有者权限，尚未使用系统凭据管理器。保存失败会报错，不宣称已持久保存。存档移动或服务器换地址会视为新作用域，需重新填写。

模型与渠道可在「设置 → 渠道/类型」选择：TokenNest 默认渠道为 `default`，OAuth 登录后可获取可用渠道，切换时刷新模型。模型类型默认自动适配 Chat Completions / Responses，也可手动指定。普通 API Key 以其绑定渠道为准，旧 OAuth 授权获取渠道列表前需重新登录并同意 `groups:read`。详见 [登录与渠道配置](docs/TOKENNEST_LOGIN.md)。
