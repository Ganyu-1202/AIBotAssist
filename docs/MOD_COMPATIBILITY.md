# 通用模组、存档与机器协作

适用 Minecraft Java 1.21.1，Fabric / NeoForge。客户端、服务器应同时更新本模组。当前实现提供真实数据查询和通用搭建能力，不内置 Create、Mekanism、AE2 等工业模组的完整设备行为模型。

## 在游戏里使用

按 K 打开 AI 对话，例如：

- “读取 JEI 中铁锭相关的配方和机器，给出这条产线的材料、步骤以及还缺哪些信息。”
- “检查坐标 100 64 200 的机器，指出输入、输出、朝向或红石哪里有问题。”
- “在我前方建自动熔炉，先预览检查，最后核对漏斗方向。”
- “根据铁块的真实配方建单原料自动合成器，告诉我放料和启动位置。”
- “读取当前 Xaero 地图路标，找出我要去的坐标。”
- “读取最近崩溃报告，按异常链说明已证实的原因和待验证的猜测。”

地图图像使用 `capture_map`：发送请求后关闭 AI 对话，打开 Xaero World Map 并保持地图可见。工具等待最多5秒；未获取时可再次请求。它只读取已打开的地图界面，不自动打开地图，不扫描其它窗口，不解码 Xaero 私有缓存。截图与当前视野共用每轮3次预算，需要支持图像输入的模型。

## 权限和指令

通用注册表、配方、公共方块状态按工具范围查询；机器库存/NBT、整个存档和服务器日志限单人存档所有者或权限等级至少2的服务器玩家。创造模式本身不授予这些服务器管理权限。

`run_commands` 保留原有严格命令范围。新增 `run_advanced_command` 允许玩家已有权限下的原版/模组命令，包括 execute、gamemode、data 和模组机器配置。必须先观察，不能与正在执行的建筑任务交错。不会给予 OP 或修改服务器权限。单人世界未开启作弊时，这个工具仍会拒绝需要权限2的操作；可通过游戏自身的作弊设置开启。

命令使用原生命令坐标语义，`~` 相对当前执行位置，与 Plan 的固定建筑原点不同。原生命令使用 Minecraft/模组自己的数量和权限限制，不经过 Plan 的4096方块限制、材料扣减或方块黑名单；请只让 AI 执行自己确实希望执行的指令。返回 submitted 只表示提交，需观察反馈和世界状态验证。

## JEI 与 Xaero

JEI 是可选 compileOnly API，固定编译基线 `jei-1.21.1-common-api:19.21.0.247`；JAR 不内嵌 JEI。Fabric 使用 `jei_mod_plugin` 入口，NeoForge 使用 `@JeiPlugin`。运行时加载/退出由 JEI 回调管理。未安装、未就绪、API不兼容均返回错误，普通服务器配方查询仍可使用。

`query_jei` 查询当前实际显示的类别、输入/输出配方、槽位及替代材料、数量、机器催化物。支持 JEI 注册的非物品成分（如流体）通用描述，但不保证捕获只绘制在界面上的能量、时间、概率、温度等信息。组件差异会标记，不能把有组件的材料当作普通物品。分页和每槽替代项均有明确截断标记。

Xaero 路标适配通过固定只读方法调用当前会话，不按文件名猜测服务器。开发时核对了官方分发的 Minimap `fabric-1.21.1-26.6.0` 类签名，以及 World Map `fabric-1.21.1-1.47.0` 的地图界面类。未对所有旧版、NeoForge 版或其它 Xaero 扩展逐一实测；API变化会返回不兼容，不能据此宣称读取成功。

## 完整存档快照

`world_snapshot(action=create)` 先请求游戏保存，再后台复制当前存档全部普通文件，包括 level.dat、玩家数据、所有维度、未加载区块、模组存档数据。session.lock 和符号链接不复制；复制错误会标记 failed，不能把失败或部分副本当作完整成功。

后续请求携带返回的 snapshot_id：status 查状态，list 分页列文件，nbt 读取 `.dat`，chunk 从 `.mca` 按绝对区块坐标读取，text 读取 JSON 等文本。NBT 的 path 使用斜杠选择键或列表下标，例如 `Data/Time`、`sections/0/block_states/palette`。chunk_x/chunk_z 是区块坐标而不是方块坐标，负数使用向下取整。读取的是副本，不把磁盘区块加载进实时世界。

快照是运行中世界的非原子副本：虽然复制前请求了保存，游戏仍继续运行，不同文件可能对应不同 tick；报告复制中变化的文件数量，但0也不证明跨文件一致。管理员做正式备份仍需自己的停服/一致性备份流程。

每个玩家在一个服务器会话内复用一份快照，务必检查 started_at，不能当成实时数据。副本保存在**存档父目录**的 `.aibotassist-snapshots/<UUID>/`，包括 save/ 和 manifest.jsonl；不会自动删除。重启后新的快照会占用更多磁盘，管理员可手动归档或删除旧副本。复制可能占用接近整个存档的磁盘空间，首次保存也可能短暂增加服务器负载。

## 机器、红石和多方块结构

`inspect_machine` 读取已加载位置的真实方块状态、邻居、六侧红石输入；有权限时附带库存和限长 NBT。NBT中没有的信息（例如某些模组的能量网络、流体能力接口）不会被虚构。`verify_result` 返回建筑偏差坐标、预期和实际状态，最多32个详细差异。

确定性模板：

| kind | 能力 | 运行前提 |
| --- | --- | --- |
| auto_smelter | 原料箱、输入漏斗、熔炉、燃料箱/漏斗、输出漏斗/箱 | 放入真实smelting原料及燃料 |
| repeater_clock | 两个4档中继器和闭合红石环 | 默认关闭，短脉冲启动；长信号可能锁成常亮 |
| auto_crafter | 真实配方对应的禁用空槽、单原料漏斗供料、输出箱、红石时钟 | 普通shaped/shapeless配方，存在同一种无组件/无容器余物原料可填所有启用槽；只放一种原料，短脉冲启动 |

模板只是计划，必须走 preview_task/execute_task，继续执行材料和保护检查。构建不赠送原料或燃料，也不跳过加工时间。NBT新增的 disabled_slots 仅允许合成器、整数0..8且不重复，不开放任意机器NBT注入。

静态建造验证忽略原版红石线邻接连接及未显式指定的实时通电/运行状态，保留朝向、延迟、合成器orientation等设计约束。机器是否工作需要隔 tick 再次检查信号/库存与真实产出；方块匹配、截图、模型说完成都不能替代运行验证。

混合材料供料、回收副产物、模组传送带/管线方向、能量、流体、多方块成形规则仍须结合实际模组信息设计。Agent 会通过 JEI/注册表/现场状态提出方案、标明未知项和可验证的问题，不自动假定所有机器支持原版漏斗或某种 NBT 字段。

## 崩溃诊断与验证范围

日志工具仅开放固定的 logs/latest.log 和 crash-reports/crash-*.txt，分页有上限，拒绝目录穿越/符号链接。常见 token/API key/password 会脱敏，但模组自定义秘密格式不保证识别。日志和世界文本均作为数据，不执行其中的指令。进程崩溃后需重启游戏才能让 Agent 分析上次报告；不会自行删除模组。

已做编译、文件副本/路径边界/脱敏、蓝图几何/方块合法性、红石状态匹配及真实 Pi SDK 离线桥接测试。真实客户端下 JEI/Xaero 画面、联机权限/保护插件、自动机器持续产出和工业模组多方块流程尚未逐项游戏内验收。
