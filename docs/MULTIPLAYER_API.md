# 多人游戏 API 策略

服务器管理员可选择两种模式，首次启动生成的配置默认为 `independent`（每人独立）。客户端和服务器需同时更新本模组。

| 模式 | API 配置和请求 | 玩家体验 |
| --- | --- | --- |
| independent（默认） | 每位玩家在自己客户端配置 API 或登录 TokenNest，直接请求个人模型服务 | 使用自己的模型、额度和登录凭据 |
| shared | 管理员配置服务器 API 地址、密钥、模型，服务器转发玩家模型请求 | 玩家无需配置个人 API 或登录，使用服务器指定的模型和额度 |

## 管理员设置

游戏内打开 `/aibot settings` →「服务器 API」→「服务器 API」，选择模式，填写共享地址、模型、新密钥并保存。单人存档所有者和服务器权限等级至少2的管理员可修改；其他玩家只能查看模式。服务器会再次检查权限，不依赖客户端按钮是否禁用。

密钥输入框留空表示保留已有服务器密钥；「清除」在保存时清除。共享模式必须有有效格式的 HTTPS 地址、非空模型 ID 和 API 密钥，否则不会保存。已有密钥不会回传给任何客户端，包括管理员；界面只显示是否已经配置。密钥不出现在命令参数中。

也可编辑服务端 `config/aibotassist-server-api.json`，然后执行 `/aibot api reload`：

```json
{
  "mode": "independent",
  "baseUrl": "https://openai.goldgom.top/v1",
  "model": "",
  "apiKey": "",
  "maxConcurrent": 4,
  "playerIntervalSeconds": 0
}
```

开启共享时填写服务商提供的真实模型 ID 和 API Key，将 mode 改为 shared。TokenNest 可使用后台创建的 API Key；服务器共享模式不复用玩家的本地 OAuth 登录令牌。

管理员命令：

- `/aibot api`：查看模式及配置方法。
- `/aibot api mode independent`：切回每人独立。
- `/aibot api mode shared`：已有共享连接参数完整时切换到共享。
- `/aibot api reload`：重读服务端配置。格式错误时保留当前有效策略；首次启动配置错误时保持默认独立并向管理员报告。

保存后立即同步在线玩家。正在进行的 AI 请求会停止，下一条消息使用新策略；已经完成的游戏操作保留。玩家原有的个人配置和本地凭据会保留，切回独立模式后可继续使用。服务端配置跨重启保存。

## 隔离与限制

聊天会话按客户端本地用户目录、连接来源（服务器地址或单人存档路径）、存档标识和实际玩家 UUID 隔离；独立/共享 API 模式均使用同样规则。服务器把存档标识保存在存档根目录的 `data/aibotassist-world-id.txt`，因此同一服务器地址更换存档也不会读取旧存档聊天。复制整个存档会保留此标识；希望副本成为全新会话时，在停服状态下删除副本的该标识文件后启动。改变服务器地址或移动单人存档路径会创建新的会话范围。

客户端将最多160条聊天及输入草稿加密保存于 `config/aibotassist/sessions/`，约每2秒保存变更，离开世界/正常退出也会提交保存；重进或重启后恢复。载入完成前禁止发送，避免把上一存档上下文带入当前世界。最近8条玩家/助手消息会用于新请求的背景，通知消息不参与；旧建造 token、运行状态和未完成工具不会恢复。换玩家 UUID、换存档或换服务器均使用独立记录，切换 API 模式不清除聊天。

聊天窗口的「清空」仅清空当前会话聊天，输入草稿独立保存。损坏、被篡改或版本不支持的记录会保留原文件，并提示当前会话无法保存，避免覆盖旧数据。聊天文件绑定身份范围，不能通过互换文件读取另一 UUID 的聊天。加密密钥 `local.key` 保存在同一目录；备份时需一起保留，加密不防御能访问本机账户文件的其他程序。未安装服务端模组的连接只能按连接来源和玩家 UUID 隔离，无法辨别远端是否替换了存档。

共享的是模型连接及额度，各玩家的聊天、建造令牌、工具任务、库存与游戏权限仍各自管理。服务器根据发送连接中的实际玩家身份收发请求，不接受请求体自报的玩家身份。服务器不维护共享对话历史，只转发当前玩家提交的上下文。

模型地址、密钥、模型及最大输出由服务器固定，客户端不能通过模型请求覆盖这些设置。普通玩家不能读取或修改共享配置；管理员也不能从界面取回已有密钥。配置文件中包含共享密钥，文件使用受限权限（POSIX系统600，Windows继承文件夹ACL），并已加入项目Git忽略规则；由服务器管理员保管。

默认允许全服最多4个并发模型请求，每位玩家同一时刻最多1个；总并发可设1–16。每玩家请求间隔默认0秒，避免中断快速的「模型→工具→模型」循环，可设0–60秒；配置非0间隔时过快请求会明确拒绝。忙、限流、上游错误不会自动重试。

单次模型请求/回执使用有大小上限的分包传输，最大8MiB。重复调用ID不会再次请求提供商。取消只影响该玩家的模型请求；玩家断线、策略切换或服务器停止会取消对应任务，旧连接的回执不会发给重连后的玩家。取消不能保证服务商退还已消耗的额度。

共享模式下，对话上下文和工具截图会经过 Minecraft 服务器，再由服务器发往共享模型服务；界面会显示这一点。独立模式仍直接从客户端请求个人模型服务。两种模式都不改变工具的服务器权限检查。

## 验证范围

自动测试覆盖默认独立配置、持久化、密钥不回传、无效共享配置拒绝、并发和玩家隔离、取消/重复ID/断线状态、固定提供商及模型、错误响应脱敏、取消上游请求。HTTP 使用可控测试客户端，不消耗真实账户额度。

Fabric/NeoForge 完整构建和现有测试继续验证。真实双客户端联机、管理员界面点击、真实共享服务商额度与请求流程仍需游戏内验收。

## 渠道与模型接口

管理员在「服务器 API → 渠道/类型」设置 `group`（默认 `default`）和 `modelProtocol`（`chat` 或 `responses`，默认 `chat`）。两种接口均支持工具与图片消息转换；客户端不能覆盖服务器固定配置。TokenNest 的普通 API Key 绑定自身渠道，应配置对应渠道的密钥；渠道请求头不会改变普通密钥绑定的路由。
