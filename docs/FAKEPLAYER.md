# 假人控制与远程取景

客户端及服务端需同时更新。仅单人存档所有者或服务器 OP2 可使用，不给假人授予 OP。Fabric 使用服务器玩家适配，NeoForge 使用其 FakePlayer API；保护/机器模组是否接受假人仍取决于各模组。

`fakeplayer_control` 每玩家最多一个假人，全服最多8个。假人为创造模式，可飞行、无重力，使用随机 UUID，名称 `AI_<所属玩家UUID前8位>`。闲置10分钟、所属玩家退出/失去权限、取消任务或停服会移除；移除清空假人库存，不转交物品。

| action | 参数与行为 |
| --- | --- |
| spawn | 可选 x/y/z、yaw/pitch、dimension、load_chunks；坐标为绝对脚部位置，默认所属玩家位置 |
| status | 返回实际位置、眼睛高度、朝向、手持物及剩余移动 tick |
| teleport | 同维度绝对脚部坐标；跨维度需 remove 后 spawn |
| look | yaw/pitch，分别设置水平和垂直朝向 |
| move | 世界坐标轴 dx/dy/dz，每 tick 向量长度最多0.4；ticks 1–200，默认20；遵循碰撞，在未加载区块前停止 |
| stop | 停止移动、物品使用和潜行 |
| sneak | enabled 布尔值 |
| equip | item 注册表 ID，count 1–64；提供创造物品，方块受禁止列表检查 |
| use_block / break | x/y/z 整数方块位置，可选 face；6格触及及视线检查，同时检查所属玩家和假人的区域保护事件 |
| attack | entity_id；6格且可见的非玩家实体 |
| remove | 移除自己的假人 |

例如先调用 `{"action":"spawn","x":100,"y":70,"z":100}`，再调用 `{"action":"move","dx":0.2,"ticks":20}`。移动开始返回 running；稍后用 status 确认实际位置，不能把预计位置当成结果。方块交互调用游戏实际放置/破坏逻辑，可能改变世界；普通玩家不能使用。

`capture_fakeplayer` 使用临时假人相机采集区域，无需移动真实玩家。默认使用已有假人眼睛位置，否则使用所属玩家眼睛；可提供任意 x/y/z **眼睛坐标**、dimension、yaw/pitch、fov（30–110），或48格内的 target_x/target_y/target_z。radius 4–16，默认16；服务端提供最多33³格的方块状态、光照和逐列生物群系，客户端用当前游戏方块模型、纹理及流体离屏渲染640×480图像，编码后交给支持图片的模型。和 capture_view/capture_map 共用每轮3张图片预算。

例如 `{"x":100,"y":80,"z":100,"target_x":110,"target_y":70,"target_z":110,"radius":16}`。未指定目标时，采样区域中心在相机前方半径的一半处。图片元数据包含区域边界、时间及未支持模型数；边界外是未知区域，不能当成空气。图像不包含实体、方块实体动态动画/NBT、粒子、天空天气模拟和光影渲染；机器/动态模组内容还需 inspect_machine、读取方块或 verify_result 核验。这是有限区域模型渲染，不是完整实时游戏相机截图。

默认 `load_chunks=false`，未加载区域明确拒绝。显式设置 true 可加载/生成：假人定位最多一个区块，区域取景最多9个区块。当前区块加载在服务器线程同步完成，新地形生成可能造成卡顿；优先对已加载区域取景。服务器只返回渲染所需数据，不传容器库存或方块实体 NBT。

已完成 Java 编译和工具桥离线测试。真实联机的假人行为、保护模组及 GPU 离屏渲染还需游戏内验证。
